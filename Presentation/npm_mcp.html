What It Is & Why It Exists

Built agent-first — the real problem depverse solves is that AI coding assistants hallucinate outdated package versions.

❌ Without depverse
Claude / Cursor / Copilot → guesses version → writes "react@17.0.0"
stale, wrong — based on training-data cutoff
✅ With depverse
Claude / Cursor / Copilot → calls get_latest_version("react") → writes "react@19.2.5"
live registry data, always current
🔥 Primary value
✓ AI coding agents writing package.json / imports
✓ Project scaffolding & dependency pinning
✓ Upgrade planning — "what changed in v2?"
✅ Useful to devs
✓ "Is this package still maintained?"
✓ License / size audits before adding a dep
✓ Quick inspection without leaving the editor
⚠️ Honest limits
– npm website & npm outdated exist
– Outside agent workflows, value drops
– Not a replacement for npm CLI
Verdict: AI coding agents suffer from stale version knowledge — no existing tool fixes this well. depverse is built around that gap, and every other tool (license, size, readme, changelog) falls out naturally.

Version Tools (6)

These tools answer "which version?" questions — latest, all, dist-tags, existence, changes.

get_latest_version
Latest Stable

Returns the current stable version string for any public npm package.

get_all_versions
Full Version List

Every version ever published, plus a count. Useful for history questions.

get_version_info
Manifest Inspector

Dependencies, devDependencies, engines, license, repository for a specific version.

get_dist_tags
Dist-Tag Map

All labels (latest, beta, next, canary…) mapped to the versions they point to.

get_changelog
Release Notes

Pulls GitHub Releases for a tag, or falls back to CHANGELOG.md from the repo.

check_version_exists
Existence Check

Boolean: does package@version exist on npm? Quick validation.

Package Info Tools (7)

These tools answer "what kind of package?" questions — metadata, readme, license, size, repo, keywords.

get_package_info
Full Metadata

Name, description, author, license, homepage, maintainers, creation date.

get_package_readme
README Content

Fetches the README markdown for the package. Truncated to 20,000 chars.

get_package_keywords
Tags / Keywords

The keyword list declared in package.json — used by npm search.

get_package_repository
Source Repo

Repository URL plus a parsed GitHub owner/repo slug when available.

get_package_homepage
Homepage / Docs

Declared homepage URL, with the npm package page URL as a fallback.

get_package_license
License Type

SPDX license string (MIT, Apache-2.0, …). Also handles legacy array form.

get_package_size
Unpacked Size & File Count

Bytes + human-readable size plus total file count from the package tarball.

Dependency Tools (5)

These tools answer "what does it need?" questions — runtime, peer, dev deps plus full tree resolution and compatibility checks.

get_dependencies
Runtime Deps

Prod dependencies with their declared version ranges — what gets installed at runtime.

get_peer_dependencies
Peer Deps

Packages the host app must provide (e.g. react-dom needs react).

get_dev_dependencies
Dev-only Deps

Build, test, and lint tools — not installed by consumers of the package.

get_dependency_tree
Full Transitive Tree

Resolves the entire nested graph in parallel. Depth-capped, with dedup caching.

check_peer_compatibility
Peer Satisfaction Check

Given what you have installed, reports whether each peer dep is satisfied (yes / no / unknown / missing). Includes a built-in npm-semver matcher covering ^, ~, comparators, and || ranges.

Try It — Example Queries

Ask Claude any of these in natural language — it picks the right tool automatically.

"What's the latest version of express?"
Claude calls get_latest_version(package_name="express").
"How many versions of lodash exist on npm?"
Calls get_all_versions and reports the count.
"What are react's dist-tags right now?"
Calls get_dist_tags(package_name="react") — shows latest, beta, next, canary.
"What changed in react 18.2.0?"
Calls get_changelog(package_name="react", version="18.2.0") — returns GitHub release body.
"How big is the react package when unpacked?"
Calls get_package_size — returns bytes, human-readable size, and file count.
"What license does express use?"
Calls get_package_license(package_name="express").
"Show me the README for zod"
Calls get_package_readme and streams back the markdown.
"Where is the source code for vue hosted?"
Calls get_package_repository — returns the repo URL and GitHub slug.
"What are the peer dependencies of react-dom?"
Calls get_peer_dependencies — shows the required react range.
"I have react 18.2.0 installed — does it work with react-dom 19?"
Calls check_peer_compatibility with the installed map — returns a per-peer yes/no.
"Show me the full dependency tree of express depth 2"
Calls get_dependency_tree with max_depth=2.
Why this is powerful: the same 18 tools, combined by Claude's reasoning, cover virtually any question about an npm package — dependency audits, upgrade planning, license checks, size audits, release inspection, peer-compat validation.
